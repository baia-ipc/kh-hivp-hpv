# prelim_analysis step 02: Mapping vs PAVE

## Overview

This step maps bucketed reads to a PAVE reference using Bowtie2, summarizes
mapping by strain, and computes coverage statistics.

## Implementation

This step is implemented as a Nextflow pipeline:

- Pipeline: `pipelines/bowtie_vs_pave.nf`
- User config: `config/user.config`
- Step path config: `config/analyses/prelim_analysis.config` (profile `preliminary_mapping_vs_pave`)
- Technical config: `config/pipelines/common.config` + `config/pipelines/bowtie_vs_pave.config`
- Bucket selection: `params.bucket_tid` in `config/pipelines/bowtie_vs_pave.config`

Wrappers:

- `bin/prelim_analysis.steps/02.mapping_vs_pave.run.sh` (all samples)
- `bin/prelim_analysis.steps/single_sample/02.mapping_vs_pave.run_sample.sh` (single sample pair)

## Inputs

- Reads directory: output of step 01 (`prelim_analysis/01.bucketing/output/`)
- PAVE reference inputs (wired via `config/pipelines/bowtie_vs_pave.config`):
  - Reference FASTA: `refdata/pave/pave_hsa.fas`
  - GFF3 directory: `refdata/pave/gff3`
  - Feature tables (derived): `derived_data/refdata/pave/features_tsv` (generated from GFF3 with `scripts/pave/gff3_to_features_tsv.run_all.sh`, or auto-generated by the pipeline)

## Outputs

Per run (`output/<RUN_ID>/`):

- per-sample mapping artifacts (SAM/BAM, indexes, and intermediate files)
Aggregated, step-level reports (`reports/`):

- mapping and strain summaries
- coverage summaries
- Strain assignment + coverage table (top strains with averaged genome/E6/E7 coverage and patient metadata)
- MultiQC report: `reports/multiqc_report.html`
